# AegisCore v2.0.0 — Companion Extension & Local Server Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implementar a extensão oficial de navegador (AegisCore Companion Extension - Manifest V3) e o mini-servidor local seguro em loopback (`127.0.0.1`) no AegisCore Desktop, permitindo detecção e preenchimento de login com 1 clique em Chrome, Brave, Edge e Firefox sem quebrar o princípio de zero telemetria e operação 100% offline.

**Architecture:** O aplicativo AegisCore Desktop executará um mini-servidor HTTP local isolado em loopback (`127.0.0.1:18291`) com thread dedicada. A extensão de navegador (Manifest V3) se comunicará exclusivamente com essa porta local através de um protocolo seguro de pareamento por token (`X-Aegis-Token`) e confirmação interativa de 6 dígitos no HUD Desktop. O Content Script da extensão detectará formulários de login, injetará badges táticos Desert Gold nos campos e preencherá credenciais autorizadas sob demanda.

**Tech Stack:** Python 3 (ThreadingHTTPServer / urllib / json), JavaScript ES6+ (Chrome Extension Manifest V3, Storage API, Content Scripts, Service Worker), CSS3 (Tema Desert Gold tático), Pytest (Testes unitários e mocks de integração).

### Task 2: Mini-Servidor Local Seguro em Loopback (`companion_server.py`)

**Files:**
- Create: `companion_server.py`
- Create: `tests/test_companion_server.py`

**Step 1: Escrever testes unitários para o servidor HTTP em loopback**
Em `tests/test_companion_server.py`, testar:
- Subir servidor em porta efêmera ou `18291` ouvindo estritamente em `127.0.0.1`.
- `GET /api/status`: retorna `{ "online": true, "unlocked": false }` sem exigir token.
- `POST /api/pair`: envia `{ "client_name": "Chrome Extension" }`, gera solicitação pendente com código de 6 dígitos.
- `POST /api/confirm-pair`: aprova token com código válido.
- `POST /api/query`: rejeita requisições sem `X-Aegis-Token` válido (401 Unauthorized).
- `POST /api/query`: com cofre desbloqueado e token válido, retorna credenciais que casam com o domínio solicitado (sem expor a senha completa no query simples, apenas IDs e metadados).
- `POST /api/get-fill`: busca com ID autorizado para preenchimento de login.

**Step 2: Executar teste para verificar falha**
Comando: `pytest tests/test_companion_server.py -v`
Resultado esperado: FAIL (módulo inexistente).

**Step 3: Implementar `companion_server.py`**
- Usar `ThreadingHTTPServer` com `BaseHTTPRequestHandler`.
- Header CORS estrito: `Access-Control-Allow-Origin: *` apenas para endpoints locais permitidos ou checando origem de extensão.
- Header customizado `X-Aegis-Token` obrigatório para endpoints protegidos.
- Prevenção contra DNS rebinding e acesso externo (garantir `client_address[0] == '127.0.0.1'`).
- Métodos para acoplamento com a instância `VaultApi`.

## Verificação e Critérios de Aceite

1. **Segurança e Isolamento:**
   - O servidor local rejeita conexões que não venham de `127.0.0.1`.
   - Nenhuma requisição a `/api/query` ou `/api/get-fill` tem sucesso sem o token de pareamento válido `X-Aegis-Token`.
   - Quando o cofre é bloqueado no AegisCore Desktop, nenhuma senha é exposta para a extensão.
2. **Usabilidade da Extensão:**
   - A extensão pode ser carregada em `chrome://extensions` (ou Edge/Brave) com 1 clique usando "Carregar sem compactação".
   - O pareamento solicita confirmação visual no aplicativo AegisCore Desktop com código de 6 dígitos.
   - Campos de login em sites (ex: GitHub, Google) exibem o escudo do AegisCore e preenchem com 1 clique.
3. **Qualidade do Código:**
   - 100% dos testes em `pytest tests/` passam sem regressões.
   - Nenhuma biblioteca externa desnecessária adicionada (mantendo o executável leve e offline).
